§0

结论先行

三个判断决定后续所有优先级。它们都来自「项目已有的数据能力」与「经典服拍卖行的市场结构」之间的差距。

判断 01 · 定位
已经是一台统计套利终端，但缺「决策层」

经典服 AH 是单边市场——没有常驻买单，只有卖家挂单，赚钱的本质是时间性套利：买相对历史均价的低估、按市价重挂（AuricDB）。本项目 7 日 P10/P50、档位、双市场、watch 高频导入全部就位，恰好是统计套利所需的全部原料；缺的只是把「展示」变成「信号」。

判断 02 · 三个金矿
最大的钱在三个没打通的地方

① 均值回归信号——有历史，没 σ 带；② 跨市场价差——联盟/中立数据已分槽，没有对比视图；③ 挂单纪律——POSTING_HISTORY 一直为空，做市与挂单管理完全空白。这三项对应三类独立收益来源：买点、搬运套利、卖出质量。

判断 03 · 稳定与长期
「稳定长期」= 高信息 + 低摩擦 + 快周转 + 严纪律

稳定赚钱不靠单次暴利，靠可重复的小优势叠加：信息优势（扫描频率）、交易成本控制（5% 税 + 时间成本都要进利润门槛）、资金周转（不碰慢动销的贵货）、风险纪律（分散 + 仓位上限）。本报告的建议按这条公式排序。

§2

稳定长期赚钱的经济学原理 → 策略映射

经典服 AH 的本质是单边市场：没有常驻买单，只有卖家的挂单，因此不存在双边价差套利，赚钱来自「时间」——在错误定价时买入、在正常定价时卖出（AuricDB 对 WoW 与 GW2 市场的关键区分）。Blizzard 官方论坛把 AH 玩法归纳为四类：纯套利 / 统计套利 / 基本面投资 / 波段交易——本项目天然适合前两类。以下 6 条原理按「稳定、长期」的标准筛选，每条都给出：原理 → 项目现状 → 优化方向 → 外部证据。

1统计套利 · 均值回归
原理：价格围绕均衡波动。持续扫描得到的价格序列可以估算「均衡区间」（如 P10–P90），当前价低于区间下沿即统计上被低估 → 买入；高于上沿 → 卖出。赚的是回归的钱，不是预测涨跌的钱。
项目现状：7 日 P10/P50 与价格变化率已有（getMed7Aggregates、daily 表），捡漏雷达用「最低价 vs 7日参考价」做启发式比较——但没有 σ / 分位区间 / 偏离度，无法回答「低 20% 算不算真低估」。
优化：基于 DailySummary 算 P10/P50/P90 + 简单 σ，首页/单品页标记「买入区 / 均衡区 / 卖出区」，把启发式门槛升级为统计口径（见 P0-1）。
证据：AuricDB —「WoW 的策略是时间性的：买当前相对历史均价被低估的物品，按正常市价重挂」；Blizzard 论坛将「统计套利」列为 AH 四大玩法之一。
2空间套利 · 跨市场价差
原理：同一物品在两个市场的价差超过「搬运成本」（跑图时间）即可套利。经典服联盟/部落 AH 互通、中立 AH 独立，本质是同一经济的两个柜台。
项目现状：联盟（PvP）与中立（PvP_N）已分槽采集同一物品的双价格——数据齐全，但没有任何「价差视图」，两价格从不对比。
优化：新增「跨市场价差」面板：同物品两市场价差排序、价差 > 门槛（税 + 跑图成本）时标「可搬运」（见 P0-2）。
证据：九游 AH 指南将「跨区/跨时段价差低买高卖」列为稳定盈利方式之一；经典服中立 AH 是独立价格形成的既有事实。
3做市与挂单纪律
原理：单边市场没有 buy order，卖出质量决定一切：挂在「sweet spot」（总卖得掉的价位）、undercut 只压 1–2%（避免价格螺旋）、材料按 20–50 堆叠吸引批量买家。
项目现状：POSTING_HISTORY 解析口子已建但一直为空——没有挂单记录，无法知道「上次挂多少、成交没有、当前占位在哪」；清单只记录「想买什么」。
优化：激活挂单历史 → 输出「建议挂单价（sweet spot）/ 建议堆叠 / undercut 提醒 / 到期重挂」（见 P1-5）。
证据：Warcraft Tavern —「sweet spot 是物品总能卖出去的那个价位」；spaceforce —「undercut 1–2% 保持竞争力而不触发价格下行螺旋；材料按 20–50 堆叠」。
4库存与资金效率
原理：回报 = 利润率 × 周转率。资金占用是隐性成本：一笔钱压在慢货上 = 机会成本；「不买贵的、慢动的投资品」是经典纪律。
项目现状：购物清单 = 「要买清单」，无资金占用、无预计周转、无 ROI——无法判断「同 1,000g 买哪批货最优」。
优化：清单升级为仓位管理：每行给「资金占用 × 预计周转 × ROI」评分并排序，提示持仓分散（见 P1-6）。
证据：Warcraft Tavern —「不要买贵的、慢动的投资」；零售/库存理论：周转率决定资本回报率。
5信息优势与时机
原理：价格信息有时效性：先看到 = 先动手。两个已被验证的窗口：采集者倾倒时段（非高峰，材料超供 → 价格暴跌 = 买点）与raid reset / 制造高峰前（需求上升 = 卖点）。
项目现状：watch 自动导入已是分钟级延迟（强），但没有「单日暴跌检测」（-20% 标买点）、没有扫描窗口建议、没有 raid reset 日历。
优化：价格异动检测 + 建议扫描窗口 + 周常/raid reset 日历提示（见 P0-3、P0-4）。
证据：mmofox —「非高峰时段监控，竞争者更少」；PewPewShop（TBC）—「采集者批量倾倒材料→超供→价格崩溃→这是你的买点；raid reset 前是制造与消耗的卖点」。
6交易成本与风险纪律
原理：每笔交易的真实成本 = 5% 拍卖税 + 时间成本 + 机会成本。利润门槛必须覆盖它们；同时分散持仓控制尾部风险，才谈得上「稳定长期」。
项目现状：利润计算已扣 5% 税（AH_CUT，好）；但没有时间成本维度、没有最小利润门槛、没有仓位上限/分散提示。
优化：按单笔规模设最小利润门槛（如 ≥ 15% 或 ≥ 税后 + 时间补偿），清单/雷达增加「仓位与分散」提示（见 P1-6、P2-11）。
证据：Warcraft Tavern —「把一切成本算进利润」；资产配置常识：分散降低尾部风险。

§4

优化建议：11 项，按优先级分三档

优先级 = 预期价值 ÷ 实施成本，且优先吃「数据已有」的低垂果实。P0 全部基于现库数据（不动采集、不动插件）；P1 需要补采集或补组件；P2 是长期工程。

PRIORITY MATRIX · 价值 × 成本
y = 预期长期收益贡献（1–10），x = 实施成本（1–10，越小越省力）；气泡 = 建议编号。P0（绿色）集中在上方左侧。

P0 · 低垂果实（本周，1–2 天，全部基于已有数据）

1均值回归带（σ + P10/P90 + 买卖区）
改什么：在 daily 数据上算每个物品 7 日窗口的 P10/P50/P90 与近似 σ（P90−P10 的稳健估计）；首页/单品页/雷达把「当前价 vs 参考价」升级为「当前价处于哪个区间」，低于 P10 标买入区、高于 P90 标卖出区。
价值：把「看着像便宜」变成「统计上确实便宜」——均值回归是本报告收益贡献最大的单一信号；成本：低，仅查询层 + 一个统计函数。
入口：getMed7Aggregates 扩展为返回分位/σ；雷达筛选加「偏离度 ≥ kσ」条件。
2跨市场价差视图（联盟 ↔ 中立）
改什么：新增「价差套利」面板：同物品两市场最新价差排序（|联盟−中立|），价差覆盖 2×税 + 跑图时间成本后标可搬运，带一键「买入低价侧 → 挂高价侧」的操作提示。
价值：双市场数据已分槽，只差一个对比查询——几乎零成本换一类独立收益；成本：低。
入口：getMarketUniverse 按双市场各取最新价，join 后按价差排序。
3价格异动检测（暴跌/暴涨触发器）
改什么：每日入库后扫 daily 最新轮：单日跌幅 ≥ 20%（参数可调）的物品进「异动榜」，标注疑似采集倾倒 / 错杀 → 买点候选；暴涨榜对应卖点候选。可叠加在 watch 导入后自动跑。
价值：采集者倾倒是最可靠的「买点」信号（PewPew 已验证），watch 已提供分钟级触发时机；成本：低。
入口：daily close 与 7 日均值对比，阈值可配；首页雷达加「异动」tab。
4扫描窗口与 raid reset 日历
改什么：在首页提示「建议扫描窗口」（非高峰时段价格波动大、竞争者少）与「raid reset / 周常重置」日历（重置前后是消耗品与材料的需求高峰 = 卖出窗口）。
价值：把「时机」变成可执行日程，强化卖出质量；成本：低，纯展示 + 日历数据。
入口：服务端一个周历常量表 + 首页横幅。

P1 · 中期（两周内，需要补采集或补组件）

5激活挂单历史（POSTING_HISTORY）→ 卖出质量
改什么：插件端把每次挂单/成交写入（口子已建），导入端解析入库；网页提供「我的挂单」：当前占位、sweet spot 建议价、undercut 提醒、到期重挂。
价值：唯一能提升「卖出质量」的数据层——做市收益的基石；成本：中，插件 + 导入 + UI 三端。
入口：PostingRecord 表已建，解析口子就绪（HANDOFF 待办）。
6清单升级为仓位管理
改什么：购物清单每行增加：资金占用（数量 × 单价）、预计周转（参考历史在售量/成交速度）、ROI 评分、分散度提示（同一材料占比 > X% 标红）。
价值：把「买什么」决策变成「怎么分配资金最优」——直接对应库存效率原理；成本：中。
入口：现有清单组件加评分列；周转用历史 quantity/auction 数的代理。
7流通分 + 可做差价榜（需求广度 × 在售 × 起伏）
改什么：流通分 = 该物品被多少个配方使用（下游配方数，需求广度）；叠加「在售门槛」（买得到）与「价格起伏分」，双高物品进「可做差价榜」，每次扫描后自动更新。
价值：起伏大 + 需求广 + 有人在卖 = 差价空间大、周转快——均值回归最赚钱的标的池；成本：中。
入口：Recipe 表数下游配方数 + daily volume + 7 日波动，全部现有数据可算。
8数据补全 + 极低价防护
改什么：转录对中立市场也扫一遍（档位 0 → 有数据）；补齐 5 条护腕成品配方；开服初期档位稀少（多数物品仅 1 档/无档位），无档位物品的每日最低价可能被 1 单极低价污染——转录覆盖扩大前，先给无档位路径加「日级在售门槛」兜底。
价值：中立档位信号闭合 + 7 日均线不被 1 单极低价拉低；成本：低-中。
入口：HANDOFF 已列明两项待办；极低价防护 = bait-filter 日级扩展。

P2 · 长期（季度内，系统工程）

9需求周期模型（阶段 + raid reset → 季节需求）
改什么：按版本阶段/周常日历建立需求系数（如 raid 重置前 3 天消耗品系数 ↑），叠加到利润与买卖信号上。
价值：从「跟随价格」进化到「预判需求」；成本：高，需要积累跨阶段数据。
10挂单执行辅助（建议价/堆叠/窗口输出）
改什么：把 P1 的挂单建议汇总为「执行卡片」：建议价、建议堆叠、建议时段、到期提醒——游戏内照做即可。
价值：把分析闭环到动作；成本：高（依赖 P1-5）。
11双服资本分配对比（eu/cn ROI）
改什么：两服各自跟踪策略收益/资金占用，给出「哪服机会更好」的资本配置建议；AH 参数分服标定。
价值：双服务器是天然的风险分散，值得显式利用；成本：中（需 cn 有数据后）。
前提：用户登录中国服、填入 AQ_AUCTIONATOR_SV_PATH_2 并重启 watch。
§5

路线图：三档推进节奏

P0 先落地（数据已有，立即可用）；P1 补采集与组件；P2 视使用情况再投入。每档结束时都有一轮「复盘」：哪类信号真实带来了收益、哪类参数要重标定。

P0 · 本周
均值回归带 + 跨市场价差 + 异动检测 + 扫描窗口
