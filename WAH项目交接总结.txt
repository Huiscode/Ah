一、项目是什么
================================================================
项目根目录：C:\Users\Hz\Documents\Workspace\Ah
用户玩的服：魔兽世界 无限服 测试服阶段（周年服类）——版本日历功能暂无用。
性质：拍卖行行情数据采集 + 短线交易决策终端。
组成：
  1) 游戏内 Lua 插件（AddOn）：自动扫描拍卖行，内存积累行情与历史点。
  2) 网页端（Next.js，:3000）：行情总览、捡漏雷达、制造利润、市场监控、
     单物品详情（盘中走势/K线/季节性/预警）、雷达参数只读跟随、版本日历。
  3) 监控进程（scripts/watch-savedvars.ts）：检测 SavedVariables 文件变化，
     自动 POST 到网页导入接口。

================================================================
二、架构与数据链路（重要，别理解错）
================================================================
插件每轮扫描 → 内存构造数据（当前轮快照 + 每物品历史点 points）→
仅在小退 / /reload 时写盘 SavedVariables（单变量 WoWderhoiAHDB）→
watch-savedvars 检测文件 mtime 变化 → POST /api/import/addon-scan → 入库。

关键点：
- 插件内存 points 每轮对每个物品追加 {t,c,q}（t=epoch秒, c=P10收盘, q=在售量），
  保留 7 日 / 每物品最多 192 点。插件不会把 points 常驻磁盘，只在写盘瞬间落盘。
- 游戏内 8 小时夜间挂机：自动扫描（/wahauto，约 15 分钟一轮）在内存积累
  points，早上小退一次写盘 → 导入器一次性把整夜全部轮次批量入库（多天日线聚合）。
  注意：插件 ADDON_LOADED 时不会从文件读回 points（内存从零开始），
  所以"早上先小退（触发导入）再重新登录"是关键流程，否则新写盘会覆盖旧点。
- 客户端禁用插件文件 IO（/wahtestio → io=nil），插件无法自读文件。
- reload 后 AuctionHouseFrame 不存在，插件无法自动重开拍卖行
  （"自动重载闭环"方案已实测证死并回滚）。

十、已知坑与注意事项
================================================================
- 不要用 ISO 字符串查 SQLite DateTime，用 epoch 毫秒数字。
- Prisma 数组事务在 SQLite 可用（createMany→update 同键 OK），
  但 route 里 effectiveExisting 只允许"快照当天"的 points 行参与快照折叠。
- DailySummary 主键是 TEXT id（Prisma 生成），手动 SQL 插入必须带 id。
- 游戏时区与用户本地不一致（美服时区），时间展示一律以欧洲/哥本哈根为准。
- watcher 进程重启后 after 从 watch-state 续读；首次 after=0 由服务端
  existingAfter 全表探针去重兜底。
- 夜间记录正确流程（务必告知用户）：挂机 → 早上先小退（触发写盘导入）
  → 再重新登录玩；确认游戏不掉线。
